# Reproducibility

LiouScope treats reproducibility as a first-class property. This document
records the guarantees, the pinned versions and the verification commands.

## Run-level guarantees

Every call to `liouscope.diagnose()` emits a `GovernanceMetadata` record:

```python
GovernanceMetadata(
    run_id          = "<SHA-256>",     # deterministic per (input, seed, framework)
    framework_version = "0.2.0",
    python_version  = ...,
    platform        = ...,
    numpy_version   = ...,
    scipy_version   = ...,
    seed            = 42,
    solver_path     = "dense" | "sparse_arpack",
    quality_label   = "stable" | "moderate" | "exploratory",
    timestamp       = "<ISO-8601>",
    input_hash      = "<SHA-256>",
)
```

`run_id` is **deterministic** for the same input matrix, seed and framework
version; it intentionally does **not** depend on the wall clock. Re-running
the same script on the same platform must produce the same `run_id`.

## Pinned versions

| Layer        | Version           |
|--------------|-------------------|
| Schema       | `D1-D24-Übersicht-v3-2026-04-24` |
| Taxonomy     | `A1-A12-v3.1`     |
| Manifest     | `1.2.0`           |
| Package      | `0.2.0`           |
| Python       | >= 3.10 (CI: 3.10, 3.11, 3.12, 3.13) |
| NumPy        | >= 1.24           |
| SciPy        | >= 1.10           |

All five strings are constants in `liouscope._consts` and are stamped on
every result.

## Seed handling

`liouscope.seed_everything(seed=42)` pins `random`, NumPy's legacy state and
`PYTHONHASHSEED`, and returns a dedicated `np.random.Generator` for callers.
Stochastic diagnostics (Haar-random initial states, bootstrap resamples,
Mpemba probes) all accept an explicit `seed=` keyword.

## Numerical anchors

The release gate `tests/test_anchors.py` encodes fourteen correctness
anchors (A--N) which were previously violated by historical or audit-flagged
bugs. They are listed in `CHANGELOG.md` and in the PR description.

## Reproducing the paper's V1--V5 table

```bash
pip install -e .
python benchmarks/reproduce_paper.py
```

Expected output: V1--V5 wall-time summary plus a SHA-256 hash. The hash is
recorded on every release tag in `CHANGELOG.md` -- any deviation must be
explained or treated as a numerical regression.

Sample (Python 3.11.15, numpy 2.4.4, scipy 1.17.1):

```
V1-qutrit                0.40s  Delta=0.2800  a=A11  verdict=CONFIRMED
V2-dephasing             0.39s  Delta=0.2500  a=A11  verdict=CONFIRMED
V3-amplitude-damped      0.49s  Delta=0.2500  a=A11  verdict=CONFIRMED
V4-thermal               0.41s  Delta=0.5410  a= A5  verdict=NOT_EXCLUDED
V5-JC                    6.70s  Delta=0.2500  a=A11  verdict=CONFIRMED
Total wall time: 8.39s
SHA-256: 20104ea1180307a60eadf5df294a76815133255a263a7e3062db72dc514f5cc7
```

## QuTiP cross-check

When QuTiP is installed (`pip install liouscope[qutip]`),
`examples/quickstart.py` cross-checks `build_liouvillian` against
`qutip.liouvillian().full()` and asserts agreement at `1e-10` atol. The
canonical observation is `1e-16` on Python 3.11 / NumPy 2.4.

## Archival identifiers

For citable archival releases we recommend:

- **Zenodo DOI** at every tagged release (enable via the
  GitHub--Zenodo integration on the repository).
- **Software Heritage SWHID** (ISO/IEC 18670:2025) generated by Software
  Heritage's automatic crawler or `swh save origin` submission.

Both are listed as gates in `LIOUSCOPE_EVIDENCE_LOCK_REGISTER.csv` and are
expected to be populated before claiming "citable archival release".

## What invalidates reproducibility

Any of the following must trigger a recorded explanation in the release
notes:

- A change in the `reproduce_paper.py` SHA-256.
- A change in the published V1--V5 numerical reference values.
- A bump in any of the pinned version strings in `liouscope._consts`.
- Modification of the anchor regression tests (`tests/test_anchors.py`).
